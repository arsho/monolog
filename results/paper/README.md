# results/paper/

**Frozen.** The exact CSVs and figures behind every number in the paper. Nothing
here is regenerated by `make benchmark` or `make plot` — a re-run writes a new
timestamped file into the relevant benchmark's own `results/` directory instead.

Produced on an NVIDIA A100-PCIE-40GB with CUDA 12.9.1, median of 3 timed runs
after one warm-up. See [`../../docs/environment.md`](../../docs/environment.md).

## Contents

```
tc/  benchmark_20260730_191855.csv    TC timings, all four versions
     gpulog_20260803_191526.csv       GPUlog TC compute times, same graphs
sg/  benchmark_20260730_202342.csv    SG timings, all four versions
     gpulog_20260803_192000.csv       GPUlog SG compute times, same graphs
cc/  benchmark_20260730_202724.csv    WCC timings, all four versions
     incremental_20260803_140631.csv  streaming WCC: incremental vs. recompute
charts/{tc,sg,cc}/                    the rendered figures
```

## CSV schema

Benchmark CSVs, column order (1-indexed):

```
version, input, iterations(3), tc|sg|cc(4), total_time(5), fileio(6), h2d(7),
setup(8), build(9), compute(10), compute_min(11), d2h(12), peak_mem_mb(13),
repeats(14), data(15)
```

with `total = fileio + h2d + setup + build + compute + d2h`. Times are
milliseconds. GPUlog CSVs use `tool, name, dataset, rows, gpulog_tc, gpulog_time_s, ...`
and report **fixpoint compute only** — compare against column `compute(10)`,
never against `total_time(5)`.

## Comparing a re-run

```bash
bash scripts/run_all.sh
diff <(cut -d, -f1-4 results/paper/tc/benchmark_20260730_191855.csv) \
     <(cut -d, -f1-4 tc_benchmark/results/benchmark_<new-ts>.csv)
```

Timing columns will jitter run to run. **Iteration counts and result sizes must
match exactly** — a difference there is a real error, not noise.
